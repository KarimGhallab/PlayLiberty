Add a playlist

The dialog the library hosts, on both clients, and the only one it hosts. It has one URL field and one choice, because CreatePlaylistInputSchema takes both, and two arrangements: a 400px centred dialog on web and a full-width sheet on mobile.

Drawn as it appears on the library. This file carries the states a person reaches by doing something to the field rather than by arriving on the screen.

The field's states

Rest, invalid, and working. The invalid one is the only place in the product a URL is refused, and the message names the host rather than saying the value is malformed, because the commonest wrong answer is a perfectly good URL from the wrong site.

Usage

Do keep the copy honest about the sync. The glossary makes a sync manual in v1, so a body saying the playlist syncs once you add it is promising something the product does not do, and the first draft of this dialog said exactly that. Do keep one field, because a second is a decision the schema has not made. Do not dismiss on a valid submission without a sync behind it: the playlist lands with a count of 0, and the detail screen's empty state is what explains that, so closing the dialog is correct and the explanation is somebody else's.

POST /playlists is a sendNotImplemented stub, so every drawing here is of a route that does not answer yet. That is a fact about the server and not about this component, and it is recorded rather than worked around.
