PlayLiberty design / form controls
Components

Form controls

The primitives every screen is assembled from. No state is carried by colour alone: a checked box has a mark, a radio has a dot, a switch has moved, an invalid input has a sentence. Every value here is a token, and every measurement was computed rather than judged.

Button

Primary carries a near-black legend on the accent, 5.85:1. The inverse is the pairing the system forbids.

Variants
States

A disabled control uses --control-disabled-fg and --control-disabled-bg, not --opacity-disabled. A blanket opacity drags the label down with the control, to 3.93:1 for ink and 2.15:1 for a muted label, both under AA. The pair measures 4.65:1 for the label on its own fill. A busy button is not a disabled one. This was a real mistake in the first draft, where the syncing button shared a rule with the disabled ones and greyed out the instant it was pressed. That reads as a refusal. Busy keeps the variant's own colours and gains a spinner, and the spinner is currentColor so it is legible on any fill without a per-variant colour to keep in step. The label stays put so the button does not change width mid-click. Under prefers-reduced-motion: reduce the ring stops turning and its cut top comes back, because a frozen ring with a notch reads as broken, and the word “Syncing” is what carries the state.

Text input

The paste target for a playlist or video URL, which is the only free text in the product.

That does not look like a link. Paste the whole URL, starting with https://

An invalid field does not turn its text red. The text stays ink so it can still be read and corrected, and the red goes on the border and on a message that says what to do about it. Colour alone would tell a user something is wrong without telling them what.

Checkbox

For adding one pasted video to several write-accessible playlists at once.

The indeterminate state is the one that is easy to forget and the one a partial selection needs, so it is drawn rather than left to whoever builds the screen. The box is --control-size-check but the row is --control-touch, because the target is the label too. The checked fill is the accent with a near-black mark at 5.85:1, not the ink: the accent is the colour this system already means actionable. These are real inputs, and the first draft was not. The boxes began as span elements inside the label, which looked identical and could not take focus: five checkboxes, none reachable by keyboard, which the ticket explicitly forbids. Native inputs with appearance: none get the role, the accessible name from the wrapping label and the whole keyboard behaviour from the platform, and restyling removes the chrome without removing any of it. The tick and the partial bar are drawn in CSS rather than typed, because a glyph is a font decision: it lands at a different size and baseline in every family that is not the one this happened to be rendered in, and this is going into a package that other people load their own fonts into. The partial state is set through the DOM property, since :indeterminate is not an attribute and cannot be written in markup.

Radio and segmented

Both drawn, because ShareLevel is a two-value choice and the two controls are not interchangeable.

Radio
Segmented

The same two values as a pair of buttons. The selected one is ink and semibold with a rule under it, and nothing is filled.

The product uses the segmented control, and the reason is that this is a setting rather than a form submit. Sharing is not a form that gets posted and forgotten; it is a permission the owner sets once and then reads back every time they look at the share list. A radio hides the other option behind a dot, and a segmented control shows both permissions side by side with the consequence spelled out under each, which is what someone checking a permission actually needs. Radio stays in the system for the cases where a choice really is a form submission, and it is drawn here so that is a decision rather than an omission. The segmented control has no fill on its selected option, and that was forced by measurement rather than chosen. The obvious build fills the selection, and it does not work here. Filling it with --surface-raised inside a --bg track measures 1.19:1, and inside the dialog it collapses to 1.00:1 because the track was already the dialog's own fill, so the selection vanished exactly where it matters most. Lifting the fill does not rescue it: every dark grey in this palette sits between 1.15:1 and 1.80:1 against these surfaces, and a grey strong enough to read starts failing the label sitting on it, since --muted on #333941 is 3.70:1. There is no room for a fill in the dark end of this palette. The selection is a rule under the option and a step from --muted to --ink, which are a shape and a contrast, so the state survives greyscale and does not depend on judging a shade.

Switch

For a boolean preference that applies immediately.

Keep removed videos Hold on to the audio when the source video disappears
Sync over mobile data Off, so syncing waits for wifi

The knob travels as well as the fill changing, so the state survives being read with no colour at all. There is no native switch element, so this is a button carrying role="switch" and aria-checked; styling a checkbox as a pill would have looked the same and lost the semantic that separates “applies immediately” from “submit this form”. A switch is only ever for a preference that takes effect at once. Anything destructive goes in a dialog with a confirm button, because a switch cannot be a warning.

Touch targets on mobile

36px tall
18px box, 44px row

A --control-height of 36px is a comfortable desktop control and too small for a thumb, so anything tappable on mobile sits inside a --control-touch of 44px. The check row does this by padding, not by growing the box, so the control looks the same size on both platforms and only its target differs.

Emphasis

The second colour, used to point at one thing rather than to decorate several.

! 3 tracks could not be downloaded. They stay in the playlist and you can retry them.
3 a count that wants you to look
The counterexample
! Do not tint the sentence as well as the rule.

Amber is --emphasis, and the downloading tone is declared as that value rather than owning one of its own: --tone-downloading: var(--emphasis). One declaration, two names, so the two cannot drift apart. The dependency points that way on purpose, because “in progress” is a mild form of “needs attention” and emphasis is the broader of the two ideas; a state borrowing a colour is ordinary, whereas a colour borrowing a state name is what this file exists to avoid. It measures 8.30:1 on --bg and 6.98:1 on --surface-raised, and a filled badge puts --bg on it at the same 8.30:1. The two can share a colour because they never compete. Download concurrency is capped at 2, so at most two rows are ever downloading at once and neither of them is the emphasis. Had that cap been 20, amber could not have been both, because a screen full of downloading rows would leave the emphasis with nothing to stand out from. Three rules hold it together. One emphasis per view, or the emphasis is the background. Always with a word, never the colour alone, which is why the counterexample above tints the sentence as well as the rule and is wrong: once the body copy is amber it stops being the thing being pointed at. And never on a hover, which is what the primary button used to do. A statement that fires every time a pointer crosses a control is not a statement, and turning the action colour into the emphasis colour meant the same button meant two different things depending on where the pointer was.

Usage

Do lift an accent fill with --accent-hover on hover and never repaint it in a tone. Do outline a control with --control-border and reserve --line for separating things that are not controls. Do give every state a mark, a word or a movement, so colour is never the message. Do use one primary action per view or per dialog. Do disable with the measured pair rather than an opacity. Do not use a switch for anything destructive. Do not use a radio for a setting the user will read back later.
