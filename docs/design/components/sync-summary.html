The colour, and what it costs

Four pairings, each measured rather than judged, and the rule is one sentence: a figure is quiet by default and takes its tone when its count is not zero.

128 kept 5.71:1
3 added 5.40:1
1 removed 7.66:1
2 failed 5.20:1

All four clear AA on --surface, and the tightest is the failed figure. The order is a scale of how much a reader needs to care, not a palette. Remove the three colours and the row still says everything, which is the point of the words under each figure.

Three saturated figures in one row, and the row is still legal. --accent #2f9e7e against --tone-failed #e0625e is 1.04:1, a 4.4% luminance gap, so in greyscale those two are the same grey and 161 degrees of hue carry all of it. Under a red-green dichromacy simulation the accent figure falls to about 3.2 on the surface, below AA, because a mid-luminance green loses its margin on a dark ground and amber and red converge on one hue. That figure carries no ratio notation because it is a simulation output and cannot be recomputed from tokens.css; the four above it can.

What is not drawn

The error sentence. SyncRun.error is not rendered here, because the sync error renders it with the reassurance about what was not lost and the retry beside it, and printing it in both places would put the same news on screen twice with two different amounts of reassurance. The three-way split is in DESIGN.md.

A playlist in error with no run to summarise. PlaylistSyncStatus.Error is reachable independently of whether a SyncRun row exists, so a client can hold a playlist in error and have nothing to draw here. That is a fault with no figures rather than a summary with no figures, and it belongs to the sync error.

The data source exists. This component binds to SyncRunSchema, and GET /api/v1/playlists/:id/sync-runs/latest returns one run. It tells "no run at all" from "a run that failed" by problem code at one status, so a client can separate this from a fault without reading the playlist first. Added in ticket 14.

Whether the surface is --surface or --bg. The list this sits above is --surface and the page behind it is --bg, and picking between them is a screen decision. Every pairing here holds either way: the tightest of the four is --tone-failed on --surface at 5.20:1, and on --bg it is further from the limit.

Usage

Do keep it to four cells and no more, because the row is a scale of concern and a fifth column has nowhere to sit on it. Do keep the figure quiet when the count is zero, and do not colour a zero in the tone of what it counts. Do keep the four words, always: the colours are the first thing a reader loses and the words are the whole message without them. Do derive the in-flight figure client-side and say so, because the contract stores no pending count and a number presented as a server fact would be a claim the server never made. Do not put the error sentence here, since the sync error owns it. Do not derive a playlist size from retainedCount: it is what one run kept, not what the playlist holds, and the header's track count is derived from the tracks the client holds for exactly this reason.
