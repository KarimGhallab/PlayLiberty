PlayLiberty design / track row
Components

Track row

The core unit, in every list. Two lines: the title, then the source and the state. Chosen over three alternatives because it is the only arrangement where the failure reason survives as a sentence rather than a truncated fragment.

Every state

Six file states, two of them drawn from two independent axes, and one more that is neither: playing is orthogonal to all of them, because a track can be stored, playing and removed at once. Stored says nothing, on purpose.

Interaction

The row itself is not a target. Only its controls are, and one of them is not there until you ask for it.

The whole row is deliberately not clickable. A row carries a title, a source, a state, a duration and a menu, and making the row a target means every one of those competes with it for the same tap. Only the controls are targets.

The play control is the one control here that is not there at rest, so it reserves its lane whether it is shown or not, is revealed by :focus-within as well as by hover, and is always visible where there is no hover at all.

Four of the seven file states have no file to play, and their control is disabled rather than absent, so the lanes still line up. Removed is not one of the four, because that track is still on disk.

This is the header's control at 28px rather than 48px, down to the accent fill and the disabled treatment, with the same --radius-chip and the same eight-frame morph from the same generator. The strip's CSS block here is byte-identical to the header's copy and check 2j compares one string against both, so neither can drift. One control rather than two costs fifteen path elements per button, so a hundred and twenty eight tracks carry 1920. The decisions behind all of this are in DESIGN.md.

At 390px the duration and the action hold their lanes and the title truncates, because those three are structural. The failure reason wraps onto a second line instead, because it is the only part of the row the user cannot reconstruct elsewhere.

The reserved lane is paid for out of the title: the title column goes from 200.4px to 160.4px, exactly 40px for a 28px control and one 12px gap. What it does not change is which rows truncate, so the lane costs slack rather than content.

Motion

The in-flight breath runs on --motion-slow. It dims the row's artwork, title, duration and menu together and restores them, so nothing travels and the text is never redrawn, which is the property the rest of this row is built around. It is deliberately shallow, to --opacity-disabled, because it moves three lanes at once and a deeper dip would cost the user the row rather than announce it. It is not the only motion here: the equalizer strip on a playing row is a loop, and the play control fades in over --motion-fast on --ease-standard.

Not a progress bar: the API carries no percentage, and a bar that implies a number the product does not have is worse than movement with no number at all. Not a highlight across the title, because a gradient behind 14px text animates a glyph run on the one element that has to stay quiet.

Under prefers-reduced-motion: reduce the breath stops and the word "Downloading" carries the state on its own. That is why the word is always present rather than being implied by the motion.

Usage

Do keep the lanes fixed, so the duration column stays a column. Do show the reason when there is one, since the user cannot reconstruct it. Do keep "Removed" dimmed rather than struck, because a strikethrough reads as deleted and the track is still playable. Do offer retry and fetch whole only where they can work, which is why only a failed fileless row's menu carries them and an unavailable one does not. Do not label the default state, since a row with nothing wrong should not announce it. Do not make the whole row a target. Do reserve the play control's lane on every row, including the ones that cannot be played, since a lane that appears and disappears moves the duration column. Do not reveal a disabled control; there is nothing to press.
